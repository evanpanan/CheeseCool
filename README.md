# CheeseCool

把好东西都存起来。

智能收藏与芝士库。

候选域名为 `cheesecool.ai`，所有权与部署地址待确认。

个人链接收藏库。在「收藏」页粘贴链接或带链接的分享文字，按回车或点击 **＋** 保存。在「芝士库」中查看列表、搜索收藏或切到关系图谱。链接先写入 Supabase，随后提取公开内容。管理员配置站点 AI 后，登录用户即可自动生成摘要和标签。配置 OpenAI 向量后，还支持语义搜索和关联。登录同一账户即可在 Mac 和 iPhone 查看同一批收藏。

## 本地启动

需要 Node.js 22.13+ 或 24，推荐使用 Node.js 24。

1. 创建 Supabase 项目，在 SQL Editor 依次执行 [001 收藏与索引](supabase/migrations/001_second_brain.sql)、[002 旧版 AI 设置](supabase/migrations/002_ai_settings.sql) 、[003 站点 AI 设置](supabase/migrations/003_site_ai_settings.sql)，再按编号执行 004、005 和 [006 知识库后端](supabase/migrations/006_knowledge_backend.sql)。再执行 007 补存历史整理结果。已有数据库只执行尚未执行的迁移。
2. 在 Supabase **Authentication → Sign In / Providers** 关闭 Email、Phone 和 Anonymous 登录，只启用 Google 与 GitHub。首次第三方授权会自动建立账号，因此保留全局 Allow new users to sign up；关闭全局新用户会连同首次 OAuth 登录一起阻止。本站不提供邮箱密码注册或登录。
3. 将 `.env.example` 复制为 `.env.local`。填入项目 URL 和 Publishable Key。旧项目也可通过 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 使用 anon key；与 Publishable Key 二选一即可。普通收藏数据权限由用户会话和 RLS 控制。
4. 安装、启动并打开 `http://localhost:3000`。

```sh
npm ci
npm run dev
```

## 站点 AI 管理

普通用户登录后直接使用站点 AI。配置由管理员统一管理，之前的个人设置停止使用，已有收藏、摘要和索引仍可查看。

1. 在 Supabase **Authentication → Users** 复制你的账号 User UID，将其设为部署变量 `AI_ADMIN_USER_IDS`。多个管理员 ID 用英文逗号分隔。
2. 在部署环境设置 `SUPABASE_SECRET_KEY`（旧版 Supabase 可用 `SUPABASE_SERVICE_ROLE_KEY`）以及用 `openssl rand -hex 32` 生成的 `AI_SETTINGS_ENCRYPTION_KEY`。服务端密钥和加密密钥均保存在部署环境中，同一数据库持续使用同一个加密密钥。
3. 登录管理员账号，打开 **站点管理**（`/settings`），选择 OpenAI、Kimi 或 DeepSeek 并保存站点 API Key。保存后立即对所有登录用户生效。只在部署后台统一配置时，也可用 `AI_PROVIDER` 和对应的服务商环境变量。

摘要和标签会使用所选服务商。语义搜索及语义连线独立使用 OpenAI 的 `text-embedding-3-small`，可在后台配置站点 OpenAI 密钥，或设置部署变量 `OPENAI_API_KEY`。只配置 Kimi 或 DeepSeek 时，仍可生成摘要、标签并显示共同标签连线。旧收藏可通过「重试处理」补充摘要或语义索引。

## 支持范围

- 普通网页通过 Open Graph 等页面元数据与 Readability 提取。
- GitHub 仓库页优先读取公开仓库 API 和 README。X 帖子使用公开嵌入接口补充正文。
- 小红书、抖音识别域名和分享链接，可提取服务端公开返回的标题、描述和封面。登录墙、风控和仅客户端可见的内容可能只保存链接。当前版本采集公开 HTML 与 API，可见视频内容未做转写。
- 关键词按片段匹配，支持中文原文子串。语义检索覆盖已索引收藏。相关收藏根据向量相似度写入 `bookmark_edges` 并在卡片中显示，并不需要额外图数据库。
- 常见跟踪参数会清理。规范化起始链接及可成功解析的重定向目标用于账户内去重。记录原始 URL、最终 URL、抓取时间和正文哈希。

## Vercel

将此项目导入 Vercel，选择 Next.js 项目和 Node.js 24。部署完整 Next.js 源码，不要使用导出的静态预览 HTML。页面、注册、登录和会话均由 Next.js 与 Supabase 处理。

1. 完成上面的 Supabase 数据库迁移。在 Vercel **Settings → Environment Variables** 至少设置 `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` 和 `NEXT_PUBLIC_SITE_URL`。公开密钥也兼容 `NEXT_PUBLIC_SUPABASE_ANON_KEY`。添加到 Production 环境，并重新部署，已有部署不会自动读取新增变量。最后一个填写当前部署的完整站点地址，例如 `https://your-app.vercel.app`，或正式自定义域名，不含路径。变量变更后重新部署。服务端 Secret Key 只用于管理员配置，不需要暴露给浏览器。
2. Supabase **Authentication → URL Configuration** 的 Site URL 填写同一站点地址。在 Redirect URLs 添加精确的 `https://你的域名/auth/callback`，本地开发可另加 `http://localhost:3000/auth/callback`。Vercel Preview 若需独立认证，为该环境分别设置自己的站点地址和回调白名单。
3. 关闭 Supabase 的 Email、Phone 和 Anonymous Provider，只启用 Google 与 GitHub。不要全局关闭新用户创建，否则新的 Google/GitHub 用户也无法首次登录。应用的 `/auth/session` 只接受白名单内的 OAuth Provider 和退出操作，旧邮箱注册、密码登录接口已移除。
4. Google Cloud Console 创建 **Web application** 类型的 OAuth Client。Authorized JavaScript origins 填写站点 origin。Authorized redirect URIs 填写 Supabase 提供的 `https://你的项目.supabase.co/auth/v1/callback`。将 Client ID 和 Client Secret 填入 Supabase **Authentication → Providers → Google** 并启用。Google 应用在 Testing 状态时需添加测试用户，对外开放时完成 Google 要求的发布配置。
5. GitHub **Settings → Developer settings → OAuth Apps → New OAuth App** 创建应用。Homepage URL 填写站点地址，Authorization callback URL 填写同一个 Supabase 回调地址 `https://你的项目.supabase.co/auth/v1/callback`。将 Client ID 和生成的 Client Secret 填入 Supabase **Authentication → Providers → GitHub** 并启用。只请求基础身份权限，不请求仓库访问权限。两家 Client Secret 均只保存在 Supabase，不要添加到 `NEXT_PUBLIC_*` 环境变量中。
6. 分别测试 Google/GitHub 首次授权、再次登录、取消授权、刷新保持会话和退出。Cookie 会话由 Supabase SSR 维护，数据访问由 RLS 按用户隔离。授权地址返回和确认退出成功后才播放离场动画，失败时显示错误并恢复按钮。

收藏处理的函数时长配置为 60 秒。

## 知识库后端与运维

- `bookmark_jobs` 为持久任务队列：保存收藏时在同一数据库事务中入队；工作进程按租约领取，最多并发领取 3 条，失败退避重试最多 4 次。进程中断后租约到期可重新领取。`after()` 只负责尽快启动，恢复保障来自数据库和 Cron。
- `vercel.json` 每分钟触发 `/api/internal/knowledge-worker`，必须配置生产环境 `CRON_SECRET`。内部接口用定时任务密钥认证，不接受普通用户调用；公开接口分别检查登录、同源请求和账号所有权。
- 原始网页快照、提取文本、来源 URL、内容哈希存入 `bookmark_sources`；历史提取文本标记 legacy。模型版本、摘要、标签、逐字证据存入 `bookmark_derivations`。导入版本单独标记，不伪装成本站采集或生成。
- 正文按重叠窗口分块；支持关键词检索。配置 OpenAI 向量密钥后分批建立 1536 维正文向量与语义关联；仅配置 DeepSeek/Kimi 时仍支持标签关联和关键词证据问答。
- `/manage` 提供编辑标题/标签/笔记、回收站恢复、重新采集、任务状态、原文版本、JSON 备份导入导出和带引用问答。人工标签和标题不会被自动整理覆盖。
- 问答仅使用当前账号可访问且未删除的来源分段；服务端校验引用的段落 ID 与原文逐字摘录，证据不足时不返回无引用的答案。这不能替代人工事实核对。
- 普通公开 HTML、GitHub 公开仓库、X 公开嵌入已支持。登录墙、仅客户端渲染的正文、受限平台音视频和飞书同步暂不保证采集；上传文件能力见下文；失败会显示读取受限，链接和笔记仍保存。此版本不宣称支持任意网站或完整多媒体采集。
- 旧版手动备份为用户下载的 JSON；另有每日加密备份和可选异地副本，见下文。单次最多 500 条收藏、1000 份来源、1000 个整理版本、10 MB；超限明确返回错误，不静默截断。导入逐条执行、自动跳过已有 URL，失败后已成功的条目会保留。手动备份包含原始资料，请自行妥善保管；不包含账号密钥或模型密钥。
- 模型问答限制为每账号每小时 20 次，收藏每账号每天 200 次，导入每天 500 次。定时任务不会对已完成条目反复调用模型。
- 安全与恢复测试：`npm test`；生产构建：`npm run build`。重点覆盖租约恢复、跨账号隔离、原件只读、回收站检索排除、模型引用校验和持久配额。

Supabase 安全检查会提示一组已登录用户可调用的 SECURITY DEFINER RPC：配额函数只使用 auth.uid() 写固定配额，重试函数先核对 auth.uid() 与收藏所有权；记录创建与分析确认函数也固定使用 auth.uid() 并核对来源所有权；均设置固定 search_path、拒绝匿名访问并有跨账号测试。这是有意的有限提权，未授予用户直接修改队列表或配额表的权限。[检查规则与说明](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)。仅服务端配置表与内部配额表无客户端策略是默认拒绝设计。


### 完整记录与材料分析

009 迁移增加随记、日记、完整对话、会议原稿、文件和人工确认的知识笔记。完整对话的角色、顺序、时间及工具调用元数据保留在只读原件中，不以摘要替代。日记保存用户选择的日期和时区。跨材料分析每次最多 6 份、22000 字符，超过时明确拒绝，不截断冒充完整分析；生成的观点与实体先保存草稿，经用户明确确认后原子发布到知识笔记和实体档案。旧原件不改写。

长文自动整理按 4500 字符分段保存中间结果，每批最多 3 段，全部分段完成后才生成最终汇总。派生记录保存 coverage（原文字符数、分段数、是否完整），中断后复用已完成段落。旧版摘要的 coverage 未知，不追溯伪造。

文档上传支持 PDF、DOCX、TXT、MD、CSV、JSON；私有存储保留原始文件和二进制 SHA-256，文本独立保存。单文件最大 200 MB（8 MiB 分片直传，断点续传），PDF 最多 200 页，DOCX 解压最多 20 MB/1000 项。音视频文件支持 mp3/wav/m4a/ogg/flac/mp4/webm；自动转写优先使用管理员配置的阿里云百炼密钥。扫描 PDF 可用百炼 Qwen OCR 逐页识别；输出被截断时明确报错，不把截断输出标记为完成。没有密钥时任务等待配置，原件仍可下载。ASR/OCR 是自动识别结果，必须允许用户核对。

附件存于私有 knowledge-originals 存储桶，只能经账号所有权校验下载。上传中断和永久删除后的对象由持久清理队列回收，已被有效记录引用的对象不会清除。备份可包含原始附件；单次附件最多 6 MB/100 个，整个 JSON 仍不得超过 10 MB。恢复后重新绑定当前账号的私有文件路径。

010 迁移保留备份恢复的导入来源标记，并为问答引用绑定原文版本。

### 与参考知识库的验收边界

- 已实现：原文采集、来源与版本保护、随记/日记、完整 AI 对话原稿、会议/交流逐字稿入库、检索与原文引用、跨材料分析草稿、确认后知识沉淀与实体档案、文件原件及 PDF/DOCX 解析、持久任务、备份恢复。
- 已有服务端实现，优先使用百炼凭证/额度，尚需管理员配置并实际检测：音视频文件转写、扫描件 OCR、向量检索。不可把“接口实现”标成“服务已开通”。
- 尚需独立集成与用户授权：飞书录音列表同步、单条妙记获取、公众号/抖音等受限平台的完整内容与媒体获取。当前这些链接可能只有公开页面信息，不能声称已提取完整视频或受限正文。
- 当前不宣称已经超过参考项目的全部能力；上述差距必须逐项通过实际来源验收后才能关闭。

生产环境验收结果与能力差距见 [后端验收记录](docs/backend-acceptance.md)。

### 检索与关联依据（第二轮）

`20261124041432_hybrid_retrieval.sql` 将关键词与向量候选分别排名，采用 RRF 融合；问答最多召回 60 个候选，每篇材料最多 3 段，再经过本地确定性重排，最终每篇最多 2 段，并去除重复段落。支持主题别名，保留版本引用。未配置或无法获取向量时明确降级到关键词；这不是已接通的外部 reranker 服务。

关联列表的「依据」展示共同主题或向量相似来源；「AI 对照原文」才触发模型。双方逐字引用校验通过后，结果保存为 AI 待核对建议，附模型和版本；不同账号不可读，任意一方版本改变或删除后旧缓存立即不可见。片段分析不能冒充全文判断，模型建议不自动修改已确认知识或新增事实关系。该分析缓存可重建；新版加密备份同时保留分析及人工核对状态。

运行 `npm run eval:retrieval` 可以执行固定虚构资料集，输出 Hit@3、MRR、空结果检查与逐题结果。当前 25 条合成回归用例，不代表真实用户资料的语义检索质量，也不是外部模型评测。

### 国内识别、长媒体与知识更新

站点管理 →「识别与检索服务」默认使用阿里云百炼。管理员单独填写百炼 API Key，现有 DeepSeek 整理服务继续使用。默认 text-embedding-v4（1536 维）、qwen3.5-ocr、paraformer-v2；密钥按用途加密，客户端不返回密钥。地域与工作空间需和百炼开通范围一致。模型名可调整；不同服务和模型的向量空间隔离，切换后后台重建索引，绝不混合比较。

先运行「实际服务检测」：固定样例分别检测向量、PDF 栅格 OCR 和音频时间戳。配置成功不代表外部服务已通过验收。自动识别可能有误，逐页、逐段结果与原件均保留，失败不伪造完整输出。

音视频最长 4 小时；单声道且不超过 2 小时可使用百炼单任务统一匿名说话人；其余按 5 分钟分段并明确标识片段内说话人，不冒充跨段身份。FFmpeg 只读取已私有保存的原件；服务使用限时签名链接。扫描 PDF 最多 200 页，每轮最多识别 2 页；空白页和文字页独立处理。正文单条上限 50 万字符，超限保存原件并明确提示拆分。每账户原件及活动上传合计 500 MB。

公开 PDF、音视频直链会流式保存全部原件（上限 200 MB）再解析。HTML/GitHub/X 保持原采集路径。受限网页可使用「内容管理」中的桌面 Chrome 扩展，用户确认后保存当前可读正文及浏览器来源；扩展不复制登录凭证，不读取隐藏内容，也不绕过付费墙、DRM 或平台限制。iOS 不支持安装此桌面扩展。飞书同步按用户要求暂缓。

「实体与知识更新」支持人工合并同类型实体、别名、历史追溯。新材料提出不同描述时进入待核对列表；接受更新前重新核对实体版本、来源版本和原文证据。关联分歧仅为模型片段分析建议，可人工确认或不采纳，来源变化后旧结果不再作为当前分析展示。

### 自动加密备份与恢复

生产环境设置稳定的 `BACKUP_ENCRYPTION_KEY`（64 位十六进制随机值），维护 Cron 每 5 分钟处理备份检查点，每账户每天最多一份，保留 7 天。数据库以单条 SQL 的一致性快照保存原文、历史版本、摘要、分段索引、关联、实体及审核历史；原始附件逐分片独立保存。临时转码缓存和未完成外部任务可从原件重建，不保存 OAuth 会话或模型密钥。每个对象使用 gzip + AES-256-GCM，每个备份独立派生密钥，写入后读回核验；任务中断后继续已完成对象。

「内容管理 → 材料工作台 → 加密备份」可查看进度和下载流式加密 ZIP；管理员下载恢复密钥并单独离线保管。仅同 Supabase 项目的备份不算异地灾备；可另外设置 `BACKUP_S3_ENDPOINT`、`BACKUP_S3_BUCKET`、`BACKUP_S3_REGION`（R2 为 auto）、`BACKUP_S3_ACCESS_KEY_ID` 和 `BACKUP_S3_SECRET_ACCESS_KEY`。配置后新备份对每个对象执行异地 PUT + GET 校验；缺少凭证时页面明确显示未配置，不宣称已完成异地副本。建议使用独立账户的私有存储桶和最小存储读写权限。

恢复到已创建的空账户（绝不覆盖现有芝士库）：

```bash
# 环境中提供目标 Supabase URL、服务端 secret、RESTORE_TARGET_USER_ID 和 BACKUP_ENCRYPTION_KEY
node --import tsx scripts/restore-backup.ts /secure/path/cheesecool-backup.zip
```

恢复工具先核对清单和每个文件，再映射结构化引用和私有存储路径；原始文字与版本哈希不改写。知识记录在一个数据库事务中发布，避免工作进程看到半份资料。恢复前后的二进制分片摘要保持一致；chunk_manifest 因私有路径变化重新计算。管理员应在独立测试账户定期做恢复演练。备份根密钥丢失后无法解密，不要把密钥和备份放在同一位置。

人工确认的实体别名参与检索扩展，按账号隔离并排除版本失效的实体来源；不会把其他用户的实体带入召回。

### 自动发现与上下文问答（2026-11-24）

原文和摘要就绪后，数据库按「收藏 + 来源哈希」原子入队自动分析，旧版本任务失效。独立 Cron 每分钟领取一轮，长材料按 8000 字符片段续跑，每份最多对照 3 份相关材料，每账户每天最多 100 轮，超过后次日继续。已完成片段不重复分析；失败退避最多 4 次，可在自动发现列表重新处理。新材料的实体只产生候选，确认后才加入实体档案；已有实体的不同描述另外进入版本审核，不静默覆盖。正文完全相同会提出重复线索，不自动删除或合并；正文相同不代表原始文件字节相同。

自动对照使用双方有限片段，保留逐字证据、来源哈希、模型及人工核对状态；候选数量有界，不代表对全库或全文做了穷尽矛盾检测。自动生成的知识笔记不会递归触发自动分析。

内容管理 → 知识问答支持持久对话（每段最多 20 轮，每账户最多 500 段，可删除）。只读取当前账户服务器保存的历史来解决指代；历史答案不作为本轮事实来源，每轮重新检索当前可见资料。复杂问题最多 4 个检索方向，汇合候选后仍限制单来源数量。百炼重排模型默认 qwen3.7-text-rerank，可在站点管理调整；服务出错时明确返回本地排序降级状态。接口依据见[百炼文本排序官方文档](https://help.aliyun.com/zh/model-studio/text-rerank-api)。

模型回答按条提供引用；无可验证逐字引用的回答条目会删除。发布对话时数据库再次核对来源版本、分段和引用，并用版本锁拒绝并发覆盖。这不等于自动证明所有语义推理都正确，用户仍可核对原文。历史引用保留当时的版本，不会被后续答案冒充当前事实。

管理页显示查询次数、降级、引用和 P95 延迟；每 5 分钟检查任务失败、处理停滞、备份异常与连续检索降级，形成按账户隔离的站内告警，恢复后自动解除。未接入外部短信、邮件或聊天通知。运行指标不存储问题原文；用户主动产生的对话历史可删除。

自动发现、审核状态和对话纳入加密备份，恢复时重映射结构化引用与归档链接。临时任务租约不沿用，避免恢复后卡住。`.github/workflows/backend-quality.yml` 在推送和 PR 时执行类型、测试、检索回归与生产构建；25 题为可重复的合成资料检查，不能代表真实用户语料上的模型质量或生产压力测试。

### 芝士库标题与站点图标

画布标题按词和字符自然换行，完整保留显示标题，不再插入省略号。悬停节点或其标题可查看完整原始标题与域名，搜索仍使用原始名称。

网页节点优先显示网站 favicon；GitHub 和 X/Twitter 使用随应用提供的平台标识。其他站点只向原站及其声明的公开图标地址读取，不向第三方图标聚合服务发送收藏域名。图标通过已登录账号的收藏所有权校验，公共网络地址逐跳检查，限制下载大小和解码尺寸；SVG 只保留静态几何元素后转换成 PNG。父页面将 PNG 数据传入隔离画布，避免第三方图片污染画布和深浅主题过渡。成功图标缓存，获取或解码失败保持默认芝士，分类通过柔和光晕与连线表达。

### 推文短标题与来源生命周期

推文节点使用简洁主题，而非将整段推文铺在画布上。模型就绪前采用完整短语或分类占位，随后由已配置的整理模型生成短标题；显示名存于属性中并绑定原文哈希和原始标题，来源变化后旧显示名立即失效。原始标题、正文、原文搜索和归档保持可用；人工修改标题优先，不被后台显示名覆盖。

内容管理 → 记录与分析 → 来源更新，可对已有网页选择手动、每天或每周检查（默认手动），也可立即检查。使用 ETag / Last-Modified 时仅向原始公开源发送条件头，不跨来源透传。每账户每日最多处理 100 轮来源检查和 100 轮短标题任务；失败退避重试最多 4 次。

重新采集改为先取回、存档和校验再切换版本，排队或抓取失败不会先清空旧内容。采用新正文时清理旧分段向量和语义关联，重新整理摘要与索引；人工标题、标签、笔记及历史原文保留。新正文显著缩短、仅获部分公开信息、输出截断或当前版本来自浏览器时，先形成候选，由本人选择采用或保留。来源版本或账号不匹配时拒绝确认；不能把登录墙和动态页面外壳当作完整文章。

GitHub 公共资料及 X 公共嵌入单独记录公开 API 原始响应，并标注 repository / repository_metadata / public_embed 的采集范围。普通 HTML 保留段落，正文最多 50 万字符；来源界限与截断明确记录。这不是完整私域、付费内容、所有推文线程或受限媒体采集，不绕过平台权限。

来源检查频率、待核对版本及任务纳入加密备份和事务恢复；来源任务失败和长时间停滞纳入站内运行告警。
