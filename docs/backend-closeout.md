## 本轮验收结果

生产 Vercel + Supabase + DeepSeek，最大 4 并发：

| 指标 | 实测 |
| --- | --- |
| 8 次独立 HTTP 收藏 | p50 1,021 ms；p95 2,402 ms |
| 全部提交后后台队列排空 | 2,109 ms；8 份原件与有效证据保留，无重复派生 |
| 4 次同源重复提交 | 保持单条记录；允许幂等成功或处理冲突时受控返回 409 |
| 检索资料规模 | 200 份、968 个分段；其中 192 份为检索合成数据，不计入收藏吞吐 |
| 12 次 HTTP 搜索 | p50 405 ms；p95 2,034 ms |
| 8 次列表读取 | p50 190 ms；p95 273 ms |
| 权限 | 外部账号不可读取或检索本人材料；未登录返回 401 |
| 清理 | 两个测试账号及测试资料已删除，原有 13 条收藏保留 |

74 项回归检查、25 条合成检索用例、类型检查和生产构建通过。临时验收入口已移除。运行日志检查未发现本轮之前 30 分钟的服务端 error/fatal 记录；这不是对所有历史运行或客户端错误的保证。

数据库顾问仍保留已登录 SECURITY DEFINER 函数提示、仅后台表默认拒绝客户端访问的提示和未启用泄露密码保护的提示。本轮验证了测试路径的账号隔离，不将其描述为完整安全审计或零告警。

## 固定范围

包含 Google/GitHub 登录、个人资料采集和原件保留、已支持格式提取、分段整理、摘要分类、关联、检索与带引用问答、版本保护、失败重试、运行监测、备份与恢复。无法完整读取的来源保留链接并明确采集范围，不伪造全文。

团队协作、完整 X 线程、所有受限平台、飞书及无限规模部署不是 V1 收尾条件。此后只修复当前范围内缺陷和实测瓶颈，不再将未来功能列为“后端没做完”。

## 容量验收边界

验收使用生产 Vercel、Supabase 和现有 DeepSeek，但只创建临时账号及合成材料。最大 4 并发；8 次独立 HTTP 采集、4 次重复采集、200 份资料的检索基线、12 次搜索和 8 次列表读取。采集 p95 预算 10 秒、搜索 p95 预算 5 秒，8 份资料后台处理预算 150 秒。每个指标只适用于该有界场景，不代表持续吞吐、服务极限或向量服务实测。

用户自己的资料不参与写入测试。测试结束注销会话并删除临时账号及其数据，临时验收路由随后移除。

## 配置阻塞的解除方式

- 国内服务：在站点管理配置百炼服务，再执行现有服务检测。未配置不写为通过，也不继续增加开发任务。
- 异地备份：提供生产环境的 `BACKUP_S3_ENDPOINT`、`BACKUP_S3_BUCKET`、`BACKUP_S3_ACCESS_KEY_ID`、`BACKUP_S3_SECRET_ACCESS_KEY`；`BACKUP_S3_REGION` 可选。密钥直接存服务端，不发到聊天。已有同项目加密备份不冒充独立异地备份。

这两个配置条件满足后，各完成一次验收即可关闭，不重新开启功能扩展。当前后端开发范围冻结；进入缺陷维护，配置阻塞不再当成新增开发任务。
