# CheeseCool 后端验收记录

日期：2026-11-23。生产环境：https://cheese-cool.vercel.app 。

本轮为独立的多账号云端知识库实现，没有复制参考仓库的代码。能力比较以真实行为为准，不用接口数量衡量完成度。

## 已验证

`npm test` 37 项通过，`npm run build` 通过。生产环境临时账号调用实际 HTTP API 和已配置的 DeepSeek，11 组验收全部返回成功：

- 已登录导入和持久任务入队。
- 跨账号读取、修改隔离。
- 人工编辑保护、软删除、回收站恢复，删除材料不进入检索。
- 真实模型整理和不可被客户端修改的原始来源、整理版本。
- 逐字校验的模型问答引用，绑定原文版本。
- JSON 备份、恢复和 URL 去重。
- 主题关系持久化。
- 私有 PDF 原件保存、实际正文提取。
- 完整 AI 对话元数据保留、文件下载、分析草稿经确认才发布，重复确认拒绝。
- 长材料逐段完成后汇总，覆盖范围记录，中间结果可续跑。
- 私有附件字节恢复和分析导入来源标记。

两个临时测试账号删除成功；生产验收路由在验收后移除。实际账号的 6 条收藏已重新索引，产生 9 条共同主题关联。

## 运行与安全边界

数据库持久队列每分钟由受密钥保护的 Cron 驱动，最多 4 次退避重试。私有附件受账号所有权校验；删除或上传中断的对象由持久清理队列回收。模型密钥仅服务端使用。所有公开数据表启用 RLS。

文件上传单个 3 MB；原稿正文 50 万字符；手动备份最多 500 条收藏、1000 来源、1000 派生版本、100 个附件/6 MB 附件、总体 10 MB，超限明确报错。这不是自动异地灾备。

Supabase advisor 的四个 authenticated SECURITY DEFINER 提示已人工审查：创建记录、确认分析、消耗配额与重试函数有固定 search_path、auth.uid() 校验和跨账号测试。只供服务端使用的配置、配额和对象清理表默认拒绝客户端访问。OAuth 登录项目仍有未开启泄露密码保护的提示，未将其描述成零告警。

## 2026-11-24：融合检索与关联依据

42 项自动化测试与生产构建通过。新增 SQL 回归包含 150 段长材料，验证候选列表截断之前先按来源限额，避免长文排挤其他来源；合成 1536 维向量覆盖仅语义匹配、双路融合和跨账号隔离。该向量测试不替代线上真实嵌入模型验收。

生产环境使用实际 DeepSeek 和两个临时账号完成 5 组检查：RRF 检索与来源多样性、共同主题依据、关系接口账号隔离、双方逐字引用与缓存复用、来源版本改变后旧分析失效。全部通过，两个临时账号已删除；真实账号仍保留 6 条收藏与 9 条关联，测试分析无残留。临时验收路由在验收后移除。

`npm run eval:retrieval` 固定 7 条虚构用例全部通过（6 条正例的 Hit@3=1、MRR=1，1 条无关问题正确返回空结果）。这是小规模回归集，不代表真实用户资料或外部语义模型的质量指标。尚需逐步补充真实任务的脱敏评测集、困难负例和引用支持度评测。

关联分析按双方原文版本缓存，展示 AI 待核对标识与双方原文链接，不自动确立事实关系；采用提供片段分析，不能冒充全文对照。缓存可重新生成，不属于原件备份内容。
